# Risks and how to handle them {#s-risks}

| Risk | Why it matters | Mitigation |
|---|---|---|
| **AI solves the worlds** | Undermines contests and assessments if rules aren't clear | Tiered AI rules; unique worlds; process scoring; formats where sustained judgement wins (Arena, Marathon, Hackathon); live "defend your fix" for finals. Never claim worlds are AI-proof |
| **Sandbox escape or abuse** | Running untrusted C on a server is risky | Containers with no network, read-only filesystems, CPU, memory and process limits; separate worker machines; keep the static checks as an extra layer |
| **Content bottleneck** | Two archetypes are not enough for a season of contests | An archetype authoring kit; one or two new archetypes a month; a review process for contributions; LLM help to *draft* archetypes, always verified by the evolution loop |
| **Unfair timing in performance worlds** | Machine noise could decide results | Time limits derived from reference runs with generous margins; the median of repeats; operation counters for Arena |
| **Generated worlds feel repetitive** | Students notice templates | More settings and variants per archetype; multi-subsystem worlds; seasonal games |
| **Cold start** | Contests need participants; courses need instructors | Start at your own university with a faculty sponsor; partner with clubs; keep student use free |
| **Founder bandwidth** | You are a first-year student with coursework | One mode at a time; recruit 2–3 co-builders from the first event; scope cuts (Chapter 2) |
| **Incumbents copy the idea** | Big platforms have distribution | Move fast on the niche (courses and competitions), build the library and community, consider partnering instead of competing |
| **Assessment validity and fairness** | Hiring use has legal and ethical weight | Don't sell assessments until there is validity and fairness evidence; start with practice and placements that don't decide outcomes alone |
| **Continuity after you graduate** | Student projects often die with the founder | Hand over to a club or the department; open-source the engine; document everything (the technical PDF already exists) |
